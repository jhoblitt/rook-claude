# Report and dashboard format (both modes)

The report (`report.md`) and dashboard (`dashboard.html`) are the advise
artifact — a maintainer works FROM them, so format rules are contract, not
style.

Dashboards are generated by `bash "${CLAUDE_PLUGIN_ROOT}/tools/run.sh" gen-pr-dashboard` /
`bash "${CLAUDE_PLUGIN_ROOT}/tools/run.sh" gen-issues-dashboard <sweep-dir>` from canonical sweep-dir
inputs ONLY — `snapshot.json` (sweep-prefetch) + `batch-*.json` +
`refs-types.json` + `skips.json` / `issues-mentions.json` — never
hand-edited, never fed from session-scratch files (a scratchpad dependency
dies with the session and forces a rebuild from prose). The scripts are
canonical for every dashboard rendering rule — CI-summary math,
reviewer/mention icon rows and tooltips, legend and column chips with
localStorage persistence, linkification, username display mangling — do
not re-derive those rules or hand-patch script output. Republish to the
SAME artifact file path per sweep so the URL stays stable; favicon stays
🗂️.

## Contract the model honors when writing report.md

- **Every issue/PR reference is a clickable link, everywhere** — tables,
  disposition text, evidence, skip rows: `[#N](url)` (the `/issues/N` URL
  form auto-redirects for PRs).
- **Ordering**: assessed rows first (by number); then a separate skipped
  section at the BOTTOM — WIP signal-rows first (they carry assessment
  data), then draft/bot/do-not-merge rows with their skip reasons. A
  WIP-titled PR is a skip-class row even though it was assessed.
- **CI cells**: ALWAYS `passing/total` computed from the snapshot's live
  `statusCheckRollup` summary (`…` only when the item has no checks at
  all) — never parsed from agent prose, never the words "green"/"red".
  The summary math (newest check suite per workflow only, dedupe by check
  name, paginate past the 100-context page — stale suites otherwise
  silently double the job count) is implemented in the scripts; never
  recompute it by hand.
- **Columns are decision-first** — PRs: #, kind, summary, CI, actions,
  disposition, issue #, assignees, reviewers, labels. Issues: #, kind,
  summary, actions, disposition, pr #, assignees, mentions, labels. The
  summary column is the item's GitHub TITLE verbatim (escaped, never
  paraphrased — triage's own judgment lives in disposition). The
  cross-reference column lists OPPOSITE-type items from the row's
  xlinks/dups, each classified Issue-vs-PullRequest via a live
  `issueOrPullRequest` lookup, never by guessing.
- **Labels column shows CURRENT labels.** Issues additionally mark
  proposed additions distinctly; PRs never get label proposals (backport
  labels belong to rook-code-review's flag-and-confirm flow).
- **Mention mining is `bash "${CLAUDE_PLUGIN_ROOT}/tools/run.sh" mine-mentions`'s job** — fence-aware
  code-stripping per comment-document, real GitHub mention semantics, and
  live login resolution (a bare `@\w+` scan turns shell prompts, emails,
  and pod names into bogus profile links). Run it — fetch + mine +
  resolve + diff — instead of re-implementing; it writes
  `issues-mentions.json` into the sweep dir and caches resolutions in
  `~/.cache/rook-triage/mentions-user-check.json`.
- **Reviewer ledger table** in the report: per-person proposed counts vs
  the per-sweep cap, and which sets were cap-swapped.
